# 웹 디자인 기준

Oracle의 남색·한지색 바탕을 유지하면서 입력 화면은 쉽게 조작하고, 풀이와 샘플은 오래 읽기 편하게 구성한다. 디자인의 기준 파일은 `web/fortune_web/static/style.css`와 `samples.css`다. 폰트는 기존 로컬 Pretendard/FortuneKorean을 사용한다.

## 색과 글자

| 역할 | 기준 |
| --- | --- |
| 기본 글자 / 보조 글자 | `#222738` / `#586174` |
| 바탕 / 문서 | `#fbf7ef` / `#fffdf8` |
| 남색 바탕 / 밝은 글자 | `#151a2e` / `#f4efe2` |
| 밝은 바탕의 강조 / 남색 바탕의 강조 | `#875e1b` / `#e8bd62` |
| 장식 구분선 / 입력·버튼 테두리 | `#ded8ca` / `#7d8794` |
| 본문 | 16px, 풀이 행간 1.75·샘플 1.8 |
| 입력 라벨·주요 안내 | 14px 이상 |
| 긴 샘플의 읽기 폭 | 최대 40rem |

오행 색은 서로 구분되는 기존 색 계열을 유지하되 타일의 흰 글자가 읽히도록 어둡게 조정한다. 색만으로 의미를 전달하지 않고 한글·한자 라벨을 함께 둔다. 장식 구분선과 조작 가능한 요소의 경계를 같은 색으로 취급하지 않는다.

## 화면 구성

- 홈은 입력 전 안내와 실제 계산 예시를 보여 준다. 예시임을 밝히는 문구를 유지한다.
- 큰 화면은 출생정보 폼과 풀이를 나란히 배치하고, 960px 이하에서는 한 열로 전환한다. 풀이를 받은 작은 화면은 기존 모바일 방식대로 결과를 먼저 보여 준다.
- 긴 풀이는 16px 본문과 넉넉한 행간으로 읽는다. 중요한 안내를 작은 글자나 낮은 대비로 숨기지 않는다.
- 해석 지수는 숫자와 설명으로 표시한다. 완료율이나 예측 확률처럼 보이는 원형 게이지는 사용하지 않는다.
- 샘플 세 상품은 비교할 수 있게 같은 구조를 유지한다. 열면 리포트가 한 행을 사용하며, 문서 내부에 상자를 반복해서 쌓지 않는다.
- 순서를 가진 단계·장 번호는 남긴다. 중복 영문 소제목, 기능을 설명하지 않는 한자 아이콘, 빈 화면의 별 장식은 덜어낸다.
- 필수 입력, 선택 입력, 성인 확인, 관심 집계, 정보 삭제, 미제공 기능과 실험 가격의 안내를 유지한다. 시각 수정으로 구매나 예측에 관한 약속을 추가하지 않는다.

## 조작과 검증

주요 입력·버튼·체크 라벨은 44px 이상 조작 영역과 명확한 키보드 포커스를 둔다. 기본 `details`, `dialog`와 기존 JavaScript 계약을 유지한다. `[hidden]`은 장식 레이아웃 규칙보다 우선한다. 모션 감소 설정을 존중한다.

변경 후에는 320·390·621·768·1440px에서 입력 전, 풀이 후, 샘플 닫힘·열림을 확인한다. 긴 본문, 표, 공유·삭제 대화상자와 키보드 이동을 별도로 살핀다. Chromium·Firefox·WebKit 자동화는 실제 휴대폰 및 인앱 브라우저 검사와 구분한다. 화면 폭을 절반으로 줄이고 DPR을 높인 검사는 확대 시 재배치의 근사 검사이며 실제 브라우저 확대 검사가 아니다.

작은 화면에서 결과를 먼저 배치하는 CSS 순서는 DOM 순서와 다르다. 제출 후 결과 제목으로 이동하는 기존 동작은 유지하지만, 저장된 세션으로 다시 방문했을 때의 모든 키보드 순서가 시각 순서와 일치한다고 간주하지 않는다.
