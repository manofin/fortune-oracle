# 웹 디자인 기준

Oracle의 한지색 바탕과 먹빛·숲색 글자를 중심으로 출생정보 입력, 계산 근거, 해석을 구분한다. 디자인의 기준 파일은 `web/fortune_web/static/style.css`와 `samples.css`다. 기존 로컬 Pretendard/FortuneKorean을 사용하며, 사용자 환경의 밝은 테마와 어두운 테마를 지원한다.

## 색과 글자

| 역할 | 밝은 테마 | 어두운 테마 |
| --- | --- | --- |
| 기본 글자 / 보조 글자 | `#192f29` / `#53675c` | `#f0f1e7` / `#b4c4b7` |
| 바탕 / 문서 | `#f6f4ed` / `#fffdf7` | `#17231f` / `#202f29` |
| 주요 행동·제목 | `#174d3d` | `#a3d5b8` |
| 강조·키보드 포커스 | `#a6422d` | `#ffab8e` |
| 장식 구분선 / 입력·버튼 테두리 | `#c9cfc2` / `#748374` | `#4a5d50` / `#819789` |
| 활용 제안 바탕 | `#e8ede3` | `#2c3e34` |

메인 화면의 기본 풀이 본문은 16px, 짧은 해석·행동·주의는 행간 1.6으로 표시한다. 계산 근거는 기본 행간 1.75를 사용하고, 560px 이하의 일일 카드 상세만 1.65로 조정한다. 긴 원문과 통합 풀이의 본문은 화면 폭과 관계없이 1.75를 유지한다. 주요 입력 라벨과 안내는 14px 이상으로 두며, 원문과 기본 풀이 상세의 읽기 폭은 최대 40rem이다. 긴 글을 숨기거나 글자를 작게 줄여 높이 기준을 맞추지 않는다.

오행 색은 구분을 돕고, 한글·한자 라벨을 함께 표시한다. 장식 구분선과 조작 가능한 요소의 테두리를 구분한다. 한지색 배경, 주홍색 `日` 인장, 숲색 주요 행동은 결과 화면과 샘플 페이지에서도 이어진다.

## 화면 구성

- 홈은 읽기를 안내하는 초대 문구와 가상 명식 예시를 보여 준다. 예시임을 밝히는 문구와 입력으로 이동하는 링크를 유지한다.
- 큰 화면은 출생정보 폼과 풀이를 나란히 배치한다. 960px 이하에서는 한 열로 전환하며, 결과를 받은 화면은 풀이를 먼저 보여 준다. 홈의 예시와 소개도 720px 이하에서 한 열로 배치한다.
- 메인 DOM에는 풀이 영역이 폼보다 먼저 있다. 입력 전에는 CSS로 폼을 먼저 배치하고, 입력 후에는 DOM과 같은 순서로 풀이를 먼저 표시한다. 상태에 따라 입력 또는 풀이로 이동하는 건너뛰기 링크를 제공한다. 제출 후 결과 제목으로 포커스를 옮기는 동작을 유지한다.
- 기본 풀이의 해석·행동·주의는 접힌 상태에서도 보인다. 상세에는 계산 근거와 한계를 구분하며, 키워드 전부를 화면과 공유 이미지에 유지한다.
- 좁은 일일 카드에서는 소제목과 첫 문장을 같은 줄에서 시작하고, 같은 근거 묶음의 짧은 문단을 이어 표시한다. 소제목과 문단의 DOM은 유지하고 묶음별 줄바꿈은 남긴다. 상세의 한글 줄바꿈은 음절 단위도 허용해 비는 줄 끝을 줄이며, 문장을 생략하거나 말줄임하지 않는다.
- 해석 지수는 숫자와 설명으로 표시한다. 완료율이나 예측 확률처럼 보이는 원형 게이지는 사용하지 않는다.
- 신살은 원진과 도화의 판정 조건, 실제로 맞은 기둥의 위치, 전통적 활용 제안을 구분한다. 결과 상태와 위치를 먼저 표시하고, 연지·일지 기준 설명은 다음 줄에 둔다. 활용 제안은 옅은 바탕으로 구분한다. 누락된 기둥을 임의로 채우거나 강도·희귀도·성격을 생성하지 않는다.
- 음력 선택·윤달 확인·지원 범위 안내는 본인과 상대 입력 폼 모두에 둔다. 양력과 음력의 입력 형식 전환, 재방문 시 원래 입력 복원, 상대 정보의 요청 후 초기화를 유지한다.
- 필수·선택 입력, 관심 집계, 정보 삭제, 미제공 기능과 실험 가격의 안내를 유지한다. 시각 수정으로 구매나 예측에 관한 약속을 추가하지 않는다.

## 조작과 검증

주요 입력·버튼·체크 라벨은 44px 이상의 조작 영역과 명확한 키보드 포커스를 둔다. 기본 `details`, `dialog`와 기존 JavaScript의 ID·이벤트 계약을 유지한다. `[hidden]`은 장식 레이아웃 규칙보다 우선한다. 좁거나 높이가 낮은 화면에서는 대화상자 내부를 스크롤할 수 있게 하며, 모션 감소 설정을 존중한다.

변경 후에는 320·390·621·768·960·1440px에서 입력 전과 풀이 후를 확인한다. 긴 본문, 신살, 음력·상대 폼, 공유·삭제 대화상자와 키보드 이동을 별도로 살핀다. 고정된 기본 풀이 회귀 사례의 접힘 높이 844px 및 390px 펼침 높이 1050px 기준은 본문 가독성과 함께 실측한다. 이 규격은 기본 풀이 카드에 적용하며 신살·통합 원문 전체를 한 화면에 담는다는 뜻은 아니다.

Chromium·Firefox·WebKit 자동화는 실제 휴대폰 및 인앱 브라우저 검사와 구분한다. 화면 폭을 절반으로 줄이고 DPR을 높인 검사는 확대 시 재배치의 근사 검사이며 실제 브라우저 확대 검사가 아니다. 스크린리더 사용성과 전체 키보드 순서는 자동 화면 검사만으로 완료 처리하지 않는다. 실행한 범위와 결과는 각 검토 기록에서 확인한다.
