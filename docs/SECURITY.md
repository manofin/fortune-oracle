# 비밀 설정과 개인정보 취급

이 소스 후보본에는 운영 비밀키·토큰·실사용자 프로필·DB·백업·로그·운영 URL·Git 이력을 포함하지 않는다. 실제 설정은 소스 트리 밖의 소유자 전용 `runtime.env`에 둔다. [생성 예시](PUBLIC_SETUP.md)는 값을 화면이나 CLI 인자에 노출하지 않고 새 파일에 직접 쓴다. `.env.example`은 빈 참고 목록이다.

## 개발·검증

처음 clone한 뒤 `git config core.hooksPath .githooks`로 로컬 commit 검사를 켠다. `python3 -B scripts/check_public_release.py --staged`는 index 전체에서 환경·인증·DB·백업·로그 파일과 자격증명 패턴을 검사한다. GitHub Actions에서도 같은 검사를 실행한다. 로컬 hook은 clone 시 자동 활성화되지 않으며, Actions는 업로드 뒤에 실행되므로 업로드 전 검사를 대신하지 않는다.

새 공개본의 최초 준비에는 `python3 -B scripts/check_public_release.py --root .`를 사용한다. 이 모드는 ignored·untracked 파일까지 검사하고, Git이 있으면 기존 이력을 물려받지 않은 단일 root commit인지 확인한다. 후속 개발에는 `--staged`를 사용한다. 어떤 자동 검사도 임의의 문장 속 개인정보를 전부 식별하지는 못하므로 fixture와 문서에는 가상 자료만 사용한다.

- 가상 성인 프로필과 임시 store/DB를 사용한다. 운영 store를 dump하거나 테스트 fixture로 복사하지 않는다.
- 로그·화면 캡처·이슈·테스트 실패 출력에는 이름, 출생정보, 좌표, 토큰, 세션 ID, 실제 프로필 키와 원문 응답을 넣지 않는다. 재현에는 값 대신 필드 존재 여부·자료형·합성 예시를 사용한다.
- 비밀값을 명령 인자, 셸 기록, `set -x`, 환경 덤프, URL에 넣지 않는다. 비밀값의 해시도 공개 보고서에 남기지 않는다.
- 외부 모델은 기본 비활성이다. 활성화 전에 전송 필드와 endpoint를 별도로 검토한다. 메시지 본문의 사용자 ID를 신뢰하지 않는다.

## 웹 데이터 경계

브라우저 세션은 현재 90일이며 계정·기기 간 복원 기능은 없다. 쿠키를 지우면 기존 정보에 접근할 수 없다. 프로필과 세션은 웹 전용 SQLite에 저장한다. 원문 쿠키는 DB에 저장하지 않으며 사용자가 다른 소유자 ID를 지정할 수 없다.

삭제·만료 시 세션 연결 기록과 프로필을 제거한다. SQLite secure_delete는 파일시스템 스냅샷이나 호스팅 백업까지 지운다는 보장이 아니다. 백업 보존·삭제는 운영자가 별도로 정해야 한다. 출생정보에서 만든 해석과 공유 카드도 익명 정보라고 부르지 않는다.

통계는 허용된 이벤트/화면 라벨만 받고 일별 세션 기준으로 중복 제거한다. 삭제·만료 시 연결 영수증은 지우지만 식별자 없는 날짜별 합계는 남는다. 외부 분석 SDK·연락처 수집·공개 통계 API는 없다.

## 문제 제보

이 후보본에는 유지관리자의 비공개 연락처를 게시하지 않는다. 공개 저장소가 실제 생성된 뒤에는 해당 호스트의 비공개 보안 제보 경로가 마련되었는지 확인한다. 공개 이슈에 작동하는 자격증명이나 개인자료를 첨부하지 않는다. 노출이 의심되면 관련 비밀값의 폐기·교체와 접근 범위를 먼저 검토하고, 제보에는 영향 범주와 합성 재현 절차만 담는다.

이 안내는 과거 사고 기록이나 보안 인증서가 아니다. 실제 서비스 운영 전에는 자신의 환경에서 접근 제어, 삭제, HTTPS, 백업과 비밀값 경계를 검증해야 한다.
