# 기본 풀이 평가 운영안

**현재 상태: 준비 중 · 자료 확정 대기 · 평가 시작 금지.** 참가 의사를 확인한 사람은 1명이며 나머지는 모집 중이다. 응답은 0건이고 품질 판정은 보류한다. 아래 P01~P05는 배정 계획이며, 참가·실제 배정·응답 완료를 뜻하지 않는다.

제품 평가 후보는 **`78893ff877b8e2c5ed480e43c3fb40d1a411ebe8`**로 유지한다. 시각 미상 안내의 수정과 검증은 [평가 전 점검 기록](basic-reading-evaluation-preflight.md)에서 확인한다. 이번 개정은 **`basic-reading-evaluation-v2-draft`**로, UI의 선택 조건을 동일하게 안내하는 평가 자료 변경이다. 제품 후보와 자료 커밋을 구분해 기록하며 자료만 바뀐 PR head를 제품 후보로 덮어쓰지 않는다. 세션마다 제품 후보·자료 커밋·manifest 해시를 대조하고, 자료 확정 전에는 참가자에게 자료를 보내거나 응답을 받지 않는다.

## 1. 두 평가를 분리한다

먼저 같은 형식의 글만 비교해 문구를 평가한다. 두 사례의 개별 응답과 쌍비교를 모두 기록한 다음, 별도 단계에서 후보 UI를 탐색한다. UI를 본 뒤 떠오른 의견은 후속 의견으로 기록하며 앞선 문구 평가를 덮어쓰지 않는다.

운영자만 [버전·자료 대응표](evaluation/operator-manifest.json)와 이 문서를 본다. 참가자에게는 `evaluation/participant/`의 승인된 안내와 해당 단계 자료 하나씩만 공개한다. 신판·구판 표기, 파일 대응표, 정답·채점 기준은 먼저 보여주지 않는다.

가리는 것은 버전 이름과 개선 여부 설명이다. 글 길이와 소제목 차이로 버전을 추측할 수 있으므로 완전한 가림으로 보고하지 않는다. 전체 PR이나 운영자 폴더를 참가자에게 보내지 않는다.

자료는 모두 가상 사례의 표현 비교용이다. 구판에는 당시 원문의 예고형·컨디션 관련 표현이 남아 있으며, 이를 현재의 권장 안내나 개인의 상태에 대한 판단으로 제시하는 것이 아니다. 원문 비교 중 불편하거나 단정적으로 읽히는 표현도 그대로 기록한다. 운영자가 평가 중 문장을 임의로 고치지 않는다.

## 2. 순서 배정

원매핑은 **1-X=신판, 1-Y=구판, 2-X=구판, 2-Y=신판**이다. 참가자 파일은 a=1-X, b=1-Y, c=2-X, d=2-Y이며 문서 제목은 모두 ‘읽기 자료’다. 이 대응은 운영자용이다.

| 익명 ID | 조건 | 사례 순서 | 각 사례의 첫 글 | 실제 공개 순서 |
| --- | --- | --- | --- | --- |
| P01 | C1 | 1→2 | 모두 신판 | 1-X(a) → 1-Y(b) → 쌍비교1 → 2-Y(d) → 2-X(c) → 쌍비교2 |
| P02 | C2 | 1→2 | 모두 구판 | 1-Y(b) → 1-X(a) → 쌍비교1 → 2-X(c) → 2-Y(d) → 쌍비교2 |
| P03 | C3 | 2→1 | 모두 신판 | 2-Y(d) → 2-X(c) → 쌍비교2 → 1-X(a) → 1-Y(b) → 쌍비교1 |
| P04 | C4 | 2→1 | 모두 구판 | 2-X(c) → 2-Y(d) → 쌍비교2 → 1-Y(b) → 1-X(a) → 쌍비교1 |
| P05 | C1 | 1→2 | 모두 신판 | P01과 같음 |

신규 참가 확정 순서대로 다음 ID와 조건을 배정한다. 이후에도 C1→C2→C3→C4 순환을 유지한다. 무작위 배정이라고 보고하지 않는다. 이탈한 사람의 ID를 새 참가자에게 재사용하거나, 결과를 본 뒤 순서를 바꾸지 않는다. 실제 배정일과 배정 인원은 모집 인원·참가 확정 인원과 별도로 기록한다.

## 3. 문구 비교 진행

1. 가상 자료임과 필수 질문·응답 방법을 안내한다. 필수란 운영자가 빠짐없이 제시한다는 뜻이며, 답을 강요하거나 개인정보를 요구하지 않는다. 찾지 못함·판단 어려움·응답하지 않음도 기록할 수 있다고 알린다.
2. 배정된 첫 글만 보여준다. 글을 다시 보며 답할 수 있다. 다섯 척도와 아래 두 재진술 질문을 먼저 기록한 뒤 다음 글을 보여준다. 정답 단어, 위치, 행동을 운영자가 먼저 알려주지 않는다.
3. 둘째 글도 같은 방식으로 평가한다. 두 글의 개별 응답을 마친 뒤 해당 사례의 쌍비교를 진행한다. 같은 절차로 다음 사례를 평가한다.

다섯 척도는 각각 1~5점이다. 1은 ‘전혀 그렇지 않음’, 5는 ‘매우 그러함’으로 안내한다. 항목을 합산하지 않는다.

- 고민 입력 없이 읽을 가치가 있다.
- 이해하기 쉽다.
- 제안한 행동을 실행할 수 있다.
- 개인적으로 느껴진다.
- 근거가 납득된다.

비유도 질문은 다음 원문을 공통으로 사용한다.

> 이 풀이를 읽고 무엇을 해볼 수 있나요?
> 제안된 행동을 찾지 못했다면 없음이라고 적어 주세요.

> 어떤 정보가 어떤 해석으로 이어졌다고 이해했나요?
> 연결을 찾지 못했다면 그대로 적어 주세요.

도움이 되거나 되지 않은 부분, 부담스럽거나 단정적으로 느껴진 문장과 이유도 기록한다. 쌍비교는 참가자에게 **첫 번째 글 / 두 번째 글 / 차이 없음 / 판단 어려움**과 이유를 받고, 운영자가 배정표에 따라 X/Y로 변환해 기록한다. 쌍비교 선택이나 개인적으로 느껴지는 정도를 다른 점수의 통과율에 더하지 않는다.

## 4. 행동 재진술 채점

말을 그대로 외웠는지가 아니라 같은 실행을 설명하는지 판정한다. 원응답을 먼저 보존하고 운영자가 나중에 채점한다. **2점만 성공**이며 1점을 절반 성공으로 계산하지 않는다.

| 자료 | 2점 | 1점 | 0점 또는 NA |
| --- | --- | --- | --- |
| 1-X 신판 | 필요한 자료를 읽고 핵심을 한 줄로 정리하는 실행을 모두 설명 | 읽기·요약 중 일부만 설명하거나 작은 실행만 언급 | 무관한 행동, 제시 후 무응답은 0 |
| 1-Y 구판 | 해당 없음 | 해당 없음 | 명시된 행동이 없어 **NA**. 운영자가 정답을 만들어 채점하지 않음 |
| 2-X 구판 | 고민을 말로 꺼내 표현하는 실행을 설명 | 머릿속으로 정리하는 정도만 설명 | 무관한 행동, 제시 후 무응답은 0 |
| 2-Y 신판 | 할 일의 마감·범위를 확인하고 쉴 여유를 남기는 핵심을 모두 설명 | 핵심의 일부만 설명 | 무관한 행동, 제시 후 무응답은 0 |

의미가 같으면 다른 표현도 인정한다. 다음 예시는 채점자용이며 참가자에게 보여주지 않는다.

| 자료 | 2점 답변 예시 | 1점 답변 예시 | 0점 답변 예시 |
| --- | --- | --- | --- |
| 1-X | “필요한 글 하나를 읽고 요점을 한 줄로 적는다” | “자료를 읽는다”, “작은 실행을 해본다” | “점수가 좋으니 준비할 필요가 없다” 또는 질문 후 무응답 |
| 1-Y | 해당 없음 | 해당 없음 | 해당 없음. “할 행동이 없다”도 원응답만 보존하고 NA |
| 2-X | “고민을 말로 표현해 본다” | “고민을 머릿속으로 정리한다” | “자료를 한 줄로 요약한다” 또는 질문 후 무응답 |
| 2-Y | “할 일의 기한과 분량을 확인하고 쉴 시간을 남긴다” | “마감만 확인한다”, “쉰다” | “점수로 건강 상태를 판단한다” 또는 질문 후 무응답 |

1-X의 핵심 요소는 읽기와 핵심 요약, 2-Y는 마감·범위 확인과 쉴 여유다. 정확한 낱말이 아니라 실행 의미를 본다. 1-X의 주의 문구만 재진술하면 1점과 `주의 문구 재진술` 표시를 남긴다. 시작 전에 채점자와 이견 검토자를 정한다. 모호한 답변은 원응답과 기준을 함께 검토하고, 합의하지 못하면 점수를 확정하지 않고 해당 사례 판정을 보류한다. 응답을 보고 새 정답 요소를 만들거나 기준을 완화하지 않는다.

1-Y의 NA는 행동 재진술 채점에만 적용한다. 행동 실행 가능성의 1~5점은 참가자의 별도 응답으로 보존한다. 구판의 재진술 결과는 참고 자료이며 신판의 성공 규칙이나 통과율에 섞지 않는다.

명시된 행동이 있는 자료에서 ‘없음’·‘모르겠다’고 답하면 원응답을 보존하고 행동 찾기 0점으로 기록한다. 답을 한 경우이므로 무응답과는 구분한다. 1-Y는 원문에 행동이 없으므로 이 경우에도 NA다.

‘질문을 제시했지만 무응답’은 행동 재진술 0점과 사유를 남긴다. ‘질문 전 이탈·기술 문제로 미실시’는 점수를 비워 두고 미실시 사유를 남긴다. 둘 다 이미 배정된 인원의 분모에서는 빼지 않는다. 반면 다섯 척도의 누락은 0점으로 채우지 않는다.

## 5. 근거 납득도와 근거 재진술

근거 납득도는 참가자가 주는 1~5점이다. 재진술은 운영자가 **정확 / 부분 / 연결 못함 / 무응답**으로 별도 기록한다. 질문 자체를 제시하지 못한 경우는 미실시로 기록하고 재진술 판정을 비워 둔다. 재진술에 새로운 80% 통과선을 만들지 않는다.

신판에서는 계산 정보와 설명 사이의 실제 연결을 확인한다. 예를 들어 1-X의 날짜 오행 토가 일간 금을 돕는 관계와 배우고 정리하는 주제, 2-Y의 날짜 오행 수가 일간 화를 제어하는 관계와 요구·여유를 점검하는 주제의 연결이다. 출력에 있는 오행 선택·가감점 연결을 정확히 설명한 경우도 기록한다. ‘믿을 만하다’는 느낌만으로 연결을 재진술했다고 보지 않는다. 구판에 없는 근거를 운영자가 보충해 정답으로 만들지 않는다.

이 검수는 글에 적힌 연결을 이해했는지 확인하는 것이며, 점술의 예측 타당성이나 실제 개인 상황을 입증하는 검사가 아니다.

## 6. 별도 UI 탐색과 후속 확인

두 사례의 문구 비교 응답을 모두 기록한 뒤 UI 과제로 넘어간다. UI 사례는 가상 A의 **2026-11-24, meeting(기대되는 만남)**으로 고정한다. 첫 화면을 제시하기 직전에 모든 참가자에게 [선택 조건 안내](evaluation/participant/ui-context.md)를 보여주며 다음 문장을 그대로 한 번 읽는다. 실제 웹·캡처·Chromium 모사에서 시점과 문장을 동일하게 유지한다.

> 이 화면은 가상 인물의 2026년 11월 24일 풀이에서 ‘기대되는 만남’을 선택한 결과입니다.

이어 접힌 화면을 제시하고 [관찰지](evaluation/participant/observation-sheet.md)의 순서로 진행한다. 해석·행동·주의를 찾는 과정, 근거를 확인하는 과정, 주저한 지점과 운영자 도움을 기록한다. 먼저 위치를 알려주거나 ‘접기를 열라’고 안내하지 않는다. 입력 조건 안내 뒤 독립적으로 탐색한 결과와 추가 도움을 준 뒤의 결과를 구분한다. 안내 문장은 선택한 날짜와 상황만 알려주며, 기본 해석과 행동·주의의 출처 대응을 먼저 설명하지 않는다.

이 과제는 **입력 조건을 알려준 상태에서의 출처 이해**를 관찰한다. 카드만 보고 선택 상황을 스스로 알아챘다는 증거로 사용하지 않는다. 고정 안내를 생략했거나 다른 설명을 더했다면 세션에 절차 이탈과 실제 안내 내용을 적는다. 안내 누락 때문에 출처를 답하지 못한 경우를 참가자의 이해 오류로 집계하지 않는다.

UI 탐색을 마친 뒤 같은 D-day 화면으로 해석과 상황 조언의 출처를 묻는다. 이어서 [범위 확인 자료](evaluation/participant/scope-check.md)로 출생시각 안내를 확인한다. 시주 질문에는 **안내를 수정한 사례 2의 신판 본문만** 다시 제시한다. 두 버전 중 어느 글에 관한 질문인지 참가자가 추측하게 하지 않는다. 이 단계에서 얻은 의견은 앞선 문구 비교 응답과 분리한다.

| 표시 방식 | 기록할 것 | 보고할 수 없는 것 |
| --- | --- | --- |
| 실제 휴대전화의 웹 | 기기·OS·브라우저·viewport, 실제 탭/스크롤/펼침 관찰 | 다른 기기까지 검증했다는 주장 |
| 캡처 보조 | 캡처 파일·해시·표시 크기, 참가자가 가리킨 위치와 이해 | 실제 웹의 터치·펼침·스크롤 동작 검증 |
| Chromium 모바일 모사 | 브라우저 버전·viewport, 모사 환경에서의 동작 | 실제 iOS/Android 기기 검증 |

캡처만 보여준 과제의 클릭·실제 스크롤 수는 0이 아니라 측정 불가로 남긴다. 서로 다른 표시 방식의 결과를 합쳐 ‘실제 모바일 검증 완료’라고 보고하지 않는다.

## 7. 집계와 판정 보류

사례별 배정 인원을 `N`, 신판에서 해당 기준을 충족한 인원을 `S`로 두고 **통과율 = S / N × 100**을 사용한다. 분모를 유효 응답자 수로 바꾸지 않는다. 배정 뒤 무응답·이탈·미실시도 N에 남긴다. 미배정 모집 인원은 N에 넣지 않는다. 아직 평가를 시작하지 않았으므로 현재 결과는 0%가 아니라 **미측정**이다.

| 신판 평가 기준 | 사례별 판단 기준 |
| --- | --- |
| 고민 없이 읽을 가치 | 4점 이상인 인원 / N ≥ 80% |
| 행동 실행 가능성 | 4점 이상인 인원 / N ≥ 80% |
| 행동 찾기 | 재진술 2점인 인원 / N ≥ 80% |
| 이해하기 쉬움 | 실제 응답 점수의 중앙값 ≥ 4 |
| 근거 납득도 | 실제 응답 점수의 중앙값 ≥ 4 |

통과 판정에 쓰는 신판의 네 척도(읽을 가치·이해도·행동 실행 가능성·근거 납득도) **각 축의 유효 점수가 5명 이상**이고, **동일 사례쌍의 두 글 모두 개별 평가를 완료한 사람이 5명 이상**이어야 판정한다. 그 전에는 수치를 적더라도 통과·실패 판정은 보류한다. 개인적으로 느껴지는 정도와 쌍 선호는 별도 기록이며 추가 통과 게이트로 사용하지 않는다. 두 글의 개별 평가 완료와 쌍 선호 무응답도 구분한다. 완료 표시가 개별 항목의 누락을 채우지는 않는다.

중앙값은 실제 1~5점만으로 계산한다. 누락을 0점으로 바꾸거나 분모를 줄여 80%를 높이지 않는다. 예를 들어 5명 배정 중 성공 4명은 4/5이고, 질문 전 이탈 1명이 있어도 4/4로 계산하지 않는다. 다만 위 네 척도의 축별 유효 응답이 5명에 못 미치면 판정은 계속 보류한다. 배정 인원·질문 제시 인원·응답 인원·축별 유효 수·누락 사유·쌍 개별 평가 완료 수·쌍 선호 응답 수를 함께 보고한다.

## 8. 기록과 시작 전 점검

[세션 기록](basic-reading-evaluation-sessions-template.csv), [문항별 응답](basic-reading-evaluation-responses-template.csv), [사례·척도별 집계](basic-reading-evaluation-summary-template.csv)는 헤더만 있는 빈 양식이다. 실제 응답 파일을 이 공개 저장소에 저장하지 않는다. 이름·연락처·실제 출생정보 대신 익명 ID만 사용한다.

결과 보고는 사례·버전·자료 묶음별로 분리한다. 배정 N / 쌍 개별평가 완료 수 / 순서별 인원, 척도별 유효 수·1~5점 분포·무응답·미실시, 성공 S/N와 중앙값, 재진술 2·1·0점·NA·미실시, 쌍 선호 각 선택 수·무응답, 문제 문장·판정 이유·수정·재검토를 함께 적는다. UI는 표시 방식별 탐색 성공·운영자 도움·오해·측정 불가를 별도 표로 보고한다. 아직 응답이 없는 칸에는 비율 0을 채우지 않는다.

각 기록에는 익명 ID, **제품 후보 전체 커밋과 평가 자료 전체 커밋**, 자료 묶음 SHA-256, 절차 revision, 배정 조건·순서, 응답 version을 남긴다. UI 자료가 별도이면 그 해시와 표시 방식도 기록한다. `ui_context_presented`에 고정 안내를 제시했는지 기록하고, 누락·추가 안내는 `notes`에 남긴다. 응답 수정은 원본을 보존하고 새 version으로 연결하며, 같은 사람의 수정본을 새 참가자로 세지 않는다.

응답 CSV는 문항당 한 행을 사용한다. `phase`는 text/pair/ui/scope, `response_status`는 answered/no_response/not_administered로 구분한다. 다섯 척도는 `score_1_to_5`, 행동 재진술은 `action_restatement_score`(0/1/2/NA), 근거 재진술은 `evidence_restatement_verdict`에 각각 기록한다. 미실시의 점수는 비워 두고 `missing_reason`에 질문 전 이탈·기술 문제 등의 사유를 남긴다. 관련 없는 점수 칸도 비워 둔다.

후보·문구·질문·채점 기준·분모 규칙·절차가 바뀌면 revision과 자료를 다시 고정한다. 변경 전 pilot 응답은 이전 묶음으로 분리하고 새 후보 결과에 합산하지 않는다. 응답을 본 뒤 유리한 채점이나 기준을 소급 적용하지 않는다.

시작 전에는 운영자가 다음 상태를 기록한다.

- 수정된 시주 안내 검토와 후보 커밋 고정 여부
- 참가자 자료·운영자 manifest의 버전 및 해시 일치 여부
- 공개 순서, 필수 질문, 표시 방식, 고정 입력 안내와 누락 사유 기록 준비 여부
- 자료 확정자·일시·확정 범위. **현재 자료는 확정 대기이며 시작하지 않는다.**
