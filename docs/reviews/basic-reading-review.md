# 고민 없는 기본 풀이 검토 기록

> 이 문서는 PR #1의 `6b892e5`까지의 변경 기록이다. PR #2의 UI와 이후 출생시각 안내 수정·평가 운영안은 [평가 전 점검](basic-reading-evaluation-preflight.md)을 확인한다. 아래의 UI 잔여 항목을 최신 상태로 간주하지 않는다.

검토일: 2026-11-15. 적용 기준은 공개 저장소 `manofin/fortune-oracle`의 `main` 커밋 `2f10b1ee25127f8930082b5b8afd9e34b7603eac`입니다. 최초 초안 `587ab85`의 채널 출력과 D-day 표시를 `05460a0`에서 보완했고, 후속 리뷰에서 발견한 D-day 행동·주의의 주제 불일치를 이번 변경에서 함께 고쳤습니다. 이 변경은 기본 일일 풀이를 검토하기 위한 초안이며, main 반영·서비스 배포·상품 출시를 뜻하지 않습니다.

## 변경 내용과 검토 자료

기존의 “말과 표현이 잘 풀리는 날” 같은 예고형 문구를, 계산 관계에 따른 성찰 주제로 바꿨습니다. 쉬운 해석 → 해볼 일 → 주의할 점 → 계산 근거 → 해석의 한계 순서로 배치했습니다. 내일과 선택일에도 쓰는 엔진이므로 “이날의 해석”, “해볼 일”처럼 날짜에 중립적인 제목을 사용합니다.

- 오행 두 개는 이 점수 규칙의 선택임을 표시하고, 동률이면 목·화·토·금·수 순서로 선택한다고 설명합니다. 정밀한 용신 판단으로 표현하지 않습니다.
- 대운이 없을 때는 계산 결과에서 적용할 구간을 확인하지 못했다고만 설명합니다. 입력 누락 등의 원인을 추측하지 않습니다.
- 계산 알고리즘·점수·등급은 유지합니다. 영어 문구는 기존 localization이 별도로 생성하므로 이번 개선 대상은 한국어입니다.
- 계산된 오행·일진·대운은 계산 결과입니다. 관계를 성찰 주제로 연결한 문장과 행동은 규칙에 따른 해석·예시입니다. 고객이 제공한 실제 생활 사실은 없습니다. `used_evidence` 같은 항목 매핑이 있더라도 해석의 타당성을 입증하는 것은 아닙니다.

### 채널별 표시와 리뷰 반영

공통 엔진의 `lines`는 웹뿐 아니라 core 메시지·Telegram·TTS·예약 발송에서도 사용했습니다. 최초 초안에서는 이 영향이 빠졌습니다. 보완본은 계산 반환값을 그대로 두고 소비 경로에서 표시를 나눕니다.

| 경로 | 보완 후 표시 |
| --- | --- |
| 웹 오늘·내일·주간 | 기존 상세를 유지하고, 앞뒤에서 반복되던 확률 한계 문장을 마지막에 한 번 표시 |
| 웹 D-day 일반 | 카드 상단에는 기본 해석, 상세에는 기본 행동 한 개 |
| 웹 D-day 시험·만남 | 기본 해석·계산값 유지. 상세의 행동과 주의 두 문단을 선택 상황에 맞춘 한 쌍으로 대체하고 각각 출처를 표시 |
| core 일일 메시지·Telegram 오늘/내일·예약 발송 | 날짜·점수·해석·행동·주의·짧은 계산 근거·한계를 요약. 상세의 오행 동률 규칙을 이어 붙이지 않음 |
| 일일 음성·내일 음성 | 같은 짧은 풀이를 TTS에 전달. 영어는 기존 현지화 문구를 유지하며 날짜·언어·풀이 시간대를 보존 |

D-day의 `reading`은 원래 계산 풀이이며 변경하지 않습니다. `text`만 선택 상황에 맞게 조립하므로, 다른 클라이언트도 화면에는 `text`를 사용해야 선택한 행동·주의가 나타납니다. `general`은 기본 행동과 주의를 유지하고 별도 성찰 질문을 더하지 않습니다. 날짜나 상황이 바뀌면 이전 D-day 결과와 진행 중인 D-day 요청을 무효화합니다.

`05460a0`에서는 만남을 골라도 wealth 관계의 금전 관련 주의가 남았습니다. 이번에는 시험·만남의 행동과 주의를 같은 설정에서 가져오며, 기존 두 문장이 각각 한 번 있는지 확인한 뒤 복사본에서 함께 바꿉니다. 한쪽만 지정하거나 문장이 없거나 중복되면 오류로 처리합니다. [고정 가상 사례의 전후 문구와 전체 응답](basic-reading-dday.md)으로 실제 변경을 확인할 수 있습니다.

이는 문단을 전부 구조화한 UI 개편은 아닙니다. 웹 요약과 기존 샘플 도구의 줄 순서 의존, 제목 요소와 문단 간격은 후속 개선으로 남깁니다. 영어 문구의 내용 개선도 이번 범위에 포함하지 않습니다. TTS 검증은 주입한 가짜 제공자에 전달된 텍스트와 미디어 계약을 확인하며 실제 음성 API 호출이나 음질 평가를 하지 않습니다.

## 검증 범위

실행 환경: Python 3.14.7, pytest 9.2.0, Node v22.23.2, 저장소의 잠금 파일로 복원한 Node 의존성. 테스트 runner의 임시 store와 네트워크 차단을 사용했습니다.

```bash
python scripts/run_fortune_tests.py \
  plugins/tests/test_fortune_oracle_basic_reading.py \
  plugins/tests/test_daily_fortune_engine.py \
  plugins/tests/test_fortune_oracle_reading_localization.py \
  plugins/tests/test_fortune_oracle_localization.py \
  plugins/tests/test_fortune_oracle_daily_short_fortune.py \
  tests/test_fortune_oracle_web.py \
  tests/test_fortune_oracle_web_schema.py \
  tests/test_fortune_oracle_web_situations.py \
  tests/test_fortune_oracle_bazi_bridge.py \
  tests/test_fortune_oracle_phase14b_dayun.py
python scripts/build_basic_reading_review.py
```

최초 초안 `587ab85`의 직접 실행 결과는 **224 passed in 15.92s** (신규 25개 + 기존 엔진 31개 + 관련 경로 168개)였습니다. 이는 선택 테스트 결과이며 전체 저장소 테스트 통과를 뜻하지 않습니다. 보완본의 재검증 결과는 아래 기록과 구분합니다.

이전 보완본 `05460a0`에서는 저장소의 Fortune 테스트 **76개 파일**을 직접 실행했습니다. 결과는 **1601 passed, 3 failed, 14 skipped in 54.22s**입니다. 실패를 제외하거나 건너뜀으로 바꾸지 않았습니다. 다음 명령으로 같은 파일 집합을 선택할 수 있습니다.

```bash
python scripts/run_fortune_tests.py $(rg --files tests plugins/tests \
  | rg '/test_(fortune_oracle.*|daily_fortune_engine)\.py$' | sort)
```

실패 3건은 별도로 추출한 공개 `main` 기준 커밋의 임시 소스에서도 동일하게 재현했습니다.

- `test_fortune_oracle_combined_english.py::test_actual_english_four_method_calculation_and_provenance`
- `test_fortune_oracle_combined_english.py::test_cli_combined_english_has_real_evidence`
- `test_fortune_oracle_routing_evidence.py::test_astrology_calculation_sources_survive_adapter_and_renderer`

서양·통합 계산을 실제 계산으로 확인하려는 기존 검사이며, 현재 환경에서 필요한 계산 근거가 나오지 않습니다. 이번 변경으로 해결했다고 처리하지 않습니다. 14개 건너뜀 역시 통과에 포함하지 않았습니다. 중간 실행에서 발견한 메시지 첫 줄의 계산 표시 누락은 수정했고, 기존 라벨 검사를 그대로 둔 최종 실행에서는 새 실패가 남지 않았습니다.

브라우저는 기본 풀이의 레이아웃 12개·표시 내용 16개·상태 6개, 기존 growth 흐름 15개·client-state 흐름 13개 검사가 통과했습니다. client-state 첫 실행의 누적 요청 제한 429는 새 임시 서버에서 단독 재검증했으며 [모바일 기록](basic-reading-mobile.md)에 구분했습니다. 모든 브라우저 스크립트를 다시 실행한 결과가 아닙니다.

관련 **6개 파일, 178 passed in 13.80s**를 직접 확인했습니다. 전체 테스트 76개 파일을 다시 실행한 수치는 아니며 위 기존 실패 3건을 해결했다고 처리하지 않습니다.

만남·시험의 wealth 날짜에서 실제 API로 행동·주의의 주제와 각각 한 개 표시를 확인했습니다. 한쪽만 지정, 빈 문구, 원문 누락·중복을 거부하는 검사와 원본 불변 검사를 추가했습니다. 고정 2026-11-24 사례의 일반·시험·만남에서 `05460a0`과 전체 `reading`이 같고, 일반 상황의 본문은 그대로임을 확인했습니다. 기존 300건의 계산 반환값 비교도 통과했습니다. 브라우저의 최신 실행 범위와 실제 전후 캡처는 [모바일 기록](basic-reading-mobile.md)에 있습니다.

- 신규 테스트는 5관계 문구와 점수, 동률·0개 오행, 대운 부재·적용, 계산 실패, 내일·선택일의 날짜 정합성을 확인합니다.
- 샘플 생성 시 가상 프로필 2개 × 30일 × 5영역 = **300건**에서 문구 이외의 모든 반환 필드가 기준 커밋과 같음을 확인했습니다. 점술의 예측 정확도를 측정한 결과가 아닙니다.
- 모바일 검사는 로컬 Chromium의 모바일 크기 모사입니다. 실제 휴대폰·Safari 검증과 구분합니다. 공개 소스에서 PDF 생성·검사 경로를 찾지 못했으므로 PDF 잘림·겹침은 **미검증**입니다.

## 기본 풀이 평가: 보완

자동 테스트와 별도로 AI 검토자가 코드 및 가상 출력을 읽었습니다. 실제 사용자 대상 가림 평가는 아직 진행하지 않았습니다. 담당자별 수락·진행 여부를 이 기록으로 대신하지 않습니다. 전후 샘플과 가림 평가지는 엔진의 기본 상세 풀이를 대상으로 하며, 채널별 요약과 D-day 선택 상황의 읽기평가를 대신하지 않습니다.

읽기 검토에서 확인한 개선:

- 짧은 행동이 계산 설명보다 먼저 나오고, 주의점과 분리됐습니다.
- 사용자의 실제 성격·상황·미래를 안다는 표현을 줄였습니다.
- 오행 선택과 동률 처리를 출력의 계산값과 대조할 수 있습니다.

남은 쟁점:

- 관계가 같으면 같은 해석·행동을 반복합니다. 5관계 문구가 다르다는 테스트만으로 개인화의 충분함을 판단할 수 없습니다.
- “주제로 읽습니다”, “기준 하나” 등이 설명서처럼 느껴질 수 있습니다. 생활에서 도움이 되는지는 읽기 평가가 필요합니다.
- 기존 등급 “아주 좋은 날”, “순풍”은 여전히 예측처럼 읽힐 수 있습니다. 점수 의미와 함께 후속 문구 검토가 필요합니다.
- 해석 근거는 관계·오행 선택·대운을 설명하지만 전체 점수 산식을 모두 풀어쓴 설명은 아닙니다.
- 웹 상세는 한 문단 요소 안에 줄바꿈으로 표시합니다. 행동과 주의는 접힌 상태에서 보이지 않습니다. 구조화된 소제목과 앞쪽 행동 배치를 후속 UI 검토 대상으로 둡니다.

## 사람의 평가 기준 제안 — Pally의 잠정 통과선

공유받은 Pally의 제안을 반영했습니다. 모바일 배치와 문구를 보완한 뒤 평가하며, 사람의 응답을 받기 전에 기준과 통과선을 확정해야 합니다. 이 문서는 잠정 제안이며 통과 판정을 미리 내리지 않습니다.

| 평가 축 | 기록 방법 | 통과선 제안 |
| --- | --- | --- |
| 고민 없이 읽을 가치 | 각 글 1~5점 + 도움이 된 문장 | 사례별 평가 대상자의 80% 이상이 변경 후 4점 이상 |
| 행동 실행 가능성 | 각 글 1~5점 + 부담스러운 행동 | 사례별 평가 대상자의 80% 이상이 변경 후 4점 이상 |
| 행동 찾기 | 해볼 일 하나를 본인 말로 설명 | 사례별 평가 대상자의 80% 이상이 제안된 행동을 설명 |
| 이해하기 쉬움 | 각 글 1~5점 + 이해되지 않은 문장 | 사례별 변경 후 중앙값 4 이상 |
| 근거의 납득도 | 각 글 1~5점 + 계산값과 문구의 연결 설명 | 사례별 변경 후 중앙값 4 이상; 경험적 타당성 입증과 구분 |
| 개인적으로 느껴지는 정도 | 각 글 1~5점 | 별도 기록, 근거 점수와 합산하지 않음 |
| 상황·미래 단정 및 위험한 조언 | 문제 문장과 이유 | 확인된 문제를 모두 수정한 뒤 재검토 |
| 모바일 탐색성 | 해석·행동·주의를 찾는 과정 관찰 | 가로 넘침·겹침 없음 + 원하는 항목 찾기 확인 |

서로 다른 평가자 5명 이상이 두 사례를 각각 평가하는 방안을 제안합니다. 사례별로 평가 대상자 수·응답 수·항목별 응답 수·누락 수를 따로 보고합니다. 80% 기준의 분모는 각 사례를 평가하도록 배정된 인원이며 미응답은 통과로 세지 않습니다(예: 5명 중 4명 이상). 중앙값에는 실제 점수만 사용하고 누락을 0점으로 바꾸지 않되, 유효 응답이 5명 미만이면 판정을 보류합니다. 행동 찾기는 원문을 외웠는지가 아니라 같은 실행을 자기 말로 설명하는지로 판정하며, 다른 행동·무응답은 통과로 세지 않습니다.

이는 사용성을 찾기 위한 소규모 검토이며 통계적 효과 입증이 아닙니다. 평가자에게 버전 대응표를 주지 않고, 각 쌍에서 X/Y/차이 없음/판단 어려움을 독립적으로 기록합니다. 개인적으로 느껴지는 정도와 유용한 글 선택은 통과율에 합산하지 않습니다. 현재 자료는 두 사례의 순서를 상쇄했으며 무작위 배정 실험을 실행하지 않았습니다. 가상 사례 읽기·사용성 점검이 실제 개인화 효과·예측 정확도·유료 가치를 입증하지 않습니다. 사람 평가는 **미실시**, 읽기 품질 합격·고민의 기여·구매 의향·결제 전환율은 모두 **미측정**입니다.
